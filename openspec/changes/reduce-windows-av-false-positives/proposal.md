# 降低 Windows 安装包杀软误报（reduce-windows-av-false-positives）

## 背景

当前本地打包得到的 Windows 安装包和 `Void.exe` 容易被杀毒软件、SmartScreen 或企业 EDR 标记为未知或可疑程序。根因不是单一代码问题，而是 Windows 桌面应用发布链路缺少可审计的签名、元数据、产物证据和误报申诉流程。

此问题现在需要处理，因为 Void 已经可以生成 `I:\自动化执行\VSCode-win32-x64\Void.exe` 和 `.build/win32-x64/user-setup/VSCodeSetup.exe`，下一步如果继续分发未治理的安装包，会影响用户安装信任和验收效率。

## 变更内容

- 新增 Windows 包信任治理能力，覆盖安装包和主程序的签名状态审计、哈希记录、版本资源记录和发布证据生成。
- 定义免费/低成本签名路线的适用边界，包括自签名、企业内部 CA、企业白名单、开源免费签名服务和误报申诉。
- 规范 Windows 产物命名和元数据，减少 `VSCode`、`Code OSS`、`Microsoft`、`Void` 混杂造成的信誉与误报风险。
- 评估并减少 Windows 安装包中的非必要 native payload，例如非 Windows 平台 prebuild 文件。
- 建立误报申诉材料模板，记录 SHA256、版本号、下载地址、应用说明、误报名称和截图等信息。
- 明确公开分发场景下免费方案的限制，不把自签名视为公网可信签名方案。

## 能力

### 新增能力

- `windows-package-trust`: 约束 Windows 打包产物的签名审计、元数据规范、免费签名路线、发布证据和杀软误报申诉流程。

### 修改能力

- 无。

## 非目标

- 不绕过、隐藏或规避杀毒软件检测逻辑。
- 不引导用户关闭杀毒软件或降低系统安全设置。
- 不要求公网用户安装自签名根证书。
- 不承诺所有安全软件零误报。
- 不在本变更中购买或接入商业 OV/EV 代码签名证书。
- 不改变 Void 的核心业务功能、语言切换功能或模型/聊天逻辑。

## 影响

- 影响 Windows 打包与发布流程，包括 `vscode-win32-x64`、`vscode-win32-x64-inno-updater`、`vscode-win32-x64-user-setup` 后的产物审计与发布准备。
- 可能影响 Inno Setup 输出名称、安装器元数据、卸载项显示名和发布文档。
- 可能影响 `.build/win32-x64` 和 `I:\自动化执行\VSCode-win32-x64\` 中的产物验证流程。
- 可能新增文档、脚本或 OpenSpec 任务，用于生成 SHA256、签名状态、版本资源和误报申诉材料。
