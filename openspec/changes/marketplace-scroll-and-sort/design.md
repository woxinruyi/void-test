# 技术设计：市场浏览体验优化

## 背景

当前 `MarketplaceBrowser` 组件的结果列表直接渲染在设置页面中，列表长度不受限制。当数据加载后（每页 20 条），整个设置页面被撑长，用户需要在页面级别滚动。搜索栏、排序筛选等操作区域会被滚出可视区域，操作不便。

现有排序类型 `'popular' | 'newest' | 'score'` 中：
- `popular` 按 `useCount`（调用量/下载量）排序 → 对应用户需求中的"下载数量"
- `newest` 按 `createdAt`（创建时间）排序 → 用户需要的是"更新时间"（`updatedAt`）
- `score` 按综合评分排序 → 对应用户需求中的"评分"
- 缺少"默认排序"选项（保持 API 返回的原始顺序）

## 目标

- 市场列表区域固定高度、内部滚动，搜索栏和操作按钮始终可见
- 排序选项改为：默认、下载数量、评分、更新时间

## 非目标

- 不修改 API 请求逻辑或数据获取链路
- 不修改卡片样式或布局
- 不引入虚拟滚动等复杂方案（当前每页 20 条，性能足够）

## 决策

### 决策 1：固定高度容器方案

**选择**：在 `MarketplaceBrowser` 的结果列表区域外层添加 `max-h-[480px] overflow-y-auto` 容器。

**替代方案**：
- A）在整个 Settings 页面层级做固定布局 → 影响范围大，需改动顶层结构
- B）使用虚拟滚动（react-window / virtualized） → 过度设计，20 条数据不需要

**理由**：最小化变更，只在 `MarketplaceBrowser` 内部调整，不影响其他设置区域。`480px` 约可显示 5-6 张卡片，足够浏览。

### 决策 2：排序类型映射

**选择**：将 `MarketplaceSortBy` 从 `'popular' | 'newest' | 'score'` 改为 `'default' | 'downloads' | 'score' | 'updated'`。

| 新排序值 | 中文标签 | 排序字段 | 排序方向 |
|---------|---------|---------|---------|
| `default` | 默认排序 | 保持 API 返回顺序 | — |
| `downloads` | 下载数量 | `useCount` | 降序 |
| `score` | 评分 | `score` | 降序 |
| `updated` | 更新时间 | `updatedAt` | 降序（最新在前） |

**理由**：`default` 保持 API 原始排序（魔搭 API 默认按热度/权重排序），用户可在此基础上切换特定维度。`downloads` 比 `popular` 语义更明确。`updated` 比 `newest` 更符合用户需求（关注最近更新而非首次创建）。

### 决策 3：默认排序选项

**选择**：组件初始 `sort` 状态设为 `'default'`（而非当前的 `'popular'`）。

**理由**：默认排序保持 API 原始顺序，避免客户端重排覆盖服务端的智能排序权重。

## 风险 / 权衡

- **[固定高度在不同分辨率下体验差异]** → 使用 `max-h-[480px]` 而非固定 `h-[480px]`，内容少时不会出现多余空白
- **[updatedAt 字段可能为空]** → 排序函数中空值降级为 0（排在最后），与现有 `createdAt` 处理一致
- **[修改 MarketplaceSortBy 类型是 breaking change]** → 仅内部使用，无外部 API 暴露，影响可控
