# Void 本地编译运行问题记录

> 记录时间：2026-04-24
> 环境：Windows 11, Node.js 20.18.2, Electron 34.3.2 (运行时), electron@41.2.1 (npm)

## 最终结论

**项目可以正常编译和运行。** 按照 `文档/开发环境操作手册.md` 的步骤操作即可。之前的启动失败完全是因为对 `node_modules/electron/` 的错误修改导致的。

### 正确的启动流程

```powershell
# 终端1：启动增量编译
npm run watch-client
# 等待 "Finished compilation with 0 errors"

# 终端2：启动 Electron
$env:NODE_ENV='development'
$env:VSCODE_DEV='1'
$env:VSCODE_CLI='1'
$env:ELECTRON_ENABLE_LOGGING='1'
& '.\.build\electron\Void.exe' . `
  --user-data-dir ./.tmp/user-data-dev `
  --extensions-dir ./.tmp/extensions
```

## 遇到的问题及解决方案

### 问题 1：ERR_REQUIRE_ESM（编译阶段）

**现象**：`npm run compile` / `npm run watch-client` 失败，报 `ERR_REQUIRE_ESM`。

**原因**：`node_modules/@vscode/gulp-electron/src/download.js` 用 `require()` 引入了 ESM-only 模块（`@electron/get`, `@octokit/rest`, `got`），Node 20 下不允许 CJS require ESM。

**解决**：执行 `node patch-gulp-electron.cjs` 将三处 `require()` 改为懒加载 `import()`。

**状态**：✅ 已解决。每次 `npm install` 后需重新执行。

---

### 问题 2：中文路径导致 watch-extensions spawn UNKNOWN

**现象**：`npm run watch`（全量监视）报 `spawn UNKNOWN`。

**原因**：项目路径含中文字符（`I:\自动化执行\void-main`），`watch-extensions` 子进程无法处理。

**解决**：使用 `npm run watch-client` 替代，仅监听核心 workbench 变化。

**状态**：✅ 已解决（规避）。

---

### 问题 3：cjsPreparseModuleExports crash（运行阶段）—— ⚠️ 根因是错误修改

**现象**：Electron 启动时报 `TypeError: Cannot read properties of undefined (reading 'exports')` at `cjsPreparseModuleExports`。

**错误根因**：对 `node_modules/electron/` 做了不当修改（添加 `exports` 字段、创建 `index.mjs`、修改 `index.js` 使用 `process._linkedBinding` 等），导致 Node.js 的 ESM→CJS 翻译器在解析模块时崩溃。

**详细分析**：
- Electron 34.3.2 的内部 ESM 解析器**原生支持** `import 'electron'`，无需任何补丁
- `node_modules/electron/` npm 包在运行时**不会被加载**，它仅用于：
  1. 开发时提供 `electron.d.ts` 类型声明
  2. 下载 Electron 二进制文件
  3. `npx electron` 启动器
- 对 `node_modules/electron/package.json` 添加 `exports` 字段，或修改 `index.js`，反而干扰了 Electron 内部解析器的正常工作，导致 Node.js 的 CJS→ESM 翻译器被错误触发

**尝试过的错误方案**：
1. 修改 `node_modules/electron/package.json` 添加 `exports` 字段 → 破坏类型解析
2. 创建 `node_modules/electron/index.mjs` ESM 入口 → 不被使用
3. 修改 `index.js` 使用 `process._linkedBinding` → 导致 native crash（`browser_init` 尚未运行）
4. CJS bootstrap 预加载模块到缓存 → 不影响 ESM 翻译器
5. `module.register()` ESM loader hook → 在 Electron 上下文中不生效
6. ESM load hook 拦截 CJS 模块 → hook 未被调用

**正确解决**：恢复 `node_modules/electron/` 到原始 npm 安装状态即可。

```powershell
# 如果 node_modules/electron 被修改，重新安装：
npm pack electron@41.2.1 --pack-destination .tmp
Remove-Item node_modules\electron -Recurse -Force
tar -xzf .tmp\electron-41.2.1.tgz -C node_modules
Rename-Item -Path node_modules\package -NewName electron
```

**状态**：✅ 已解决。

### 问题 4：React duplicate key 警告（非致命）

**现象**：运行时控制台出现 `Encountered two children with the same key` 警告，涉及 `claude-sonnet-4-6aiyiwei` 等 key。

**原因**：Void 侧边栏模型列表中存在重复 key 的 React 组件。

**影响**：不影响功能，仅控制台警告。

**状态**：⚠️ 存在但不阻塞。建议后续修复模型列表的 key 生成逻辑。

## 关键经验教训

1. **不要修改 `node_modules/electron/`**：Electron 的 ESM 解析器在 C++ 层处理 `import 'electron'`，不经过 `node_modules`。任何对 npm 包的修改只会干扰正常流程。

2. **`process._linkedBinding` 在 bootstrap 阶段不可用**：Electron 的 `browser_init`（设置 `process.type`、注册 linked bindings）在用户代码加载之后才完成初始化。

3. **`module.register()` 在 Electron 的 default_app 上下文中可能不生效**：ESM loader hooks 在标准 Node.js 中有效，但 Electron 的模块加载链路有差异。

4. **遵循操作手册**：项目的 `文档/开发环境操作手册.md` 已经包含了正确的操作流程，无需额外的 hack 或 shim。
