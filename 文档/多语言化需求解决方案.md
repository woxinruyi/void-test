# Void 编辑器多语言化 — 执行方案

> 更新：2026-04-13 | 状态：**阶段一执行中**

---

## 一、方案概述

自建轻量 i18n 模块（`t()` + `useLocale()`），在 Onboarding 首屏增加语言下拉选择器，默认简体中文，支持切换英文。React UI 即时生效；VSCode 原生 UI 通过语言包 + 重启生效。

**不用 react-i18next**（+50KB、构建风险）、**不接入 VSCode NLS**（React 走独立 tsup 构建，无法使用 NLS 编译管线）。

| 范围 | 影响 | 风险 |

## 六、审核检查清单（Code Review Checklist）

### 6.1 代码质量

- [ ] `TranslationKeys` 接口中每个 key 在 `en.ts` 和 `zh-cn.ts` 中都有对应值
- [ ] `t()` 函数对不存在的 key 有 fallback（返回英文 → 返回 key 本身）
- [ ] `useLocale()` Hook 正确清理 listener（避免内存泄漏）
- [ ] `LanguageSelector` 使用 `select` 而非自定义下拉（减少复杂度）
- [ ] 无遗漏的硬编码字符串（`VoidOnboarding.tsx` 中所有用户可见文字已替换）
- [ ] 未修改任何非 Onboarding 文件的功能逻辑

### 6.2 构建 & 集成

- [ ] 新文件路径在 `react/src/` 下，可被 scope-tailwind 和 tsup 正确处理
- [ ] 新文件不包含 Tailwind CSS class（纯逻辑文件，scope-tailwind 处理无副作用）
- [ ] import 路径使用 `.js` 后缀（ESM 要求）
- [ ] `node build.js` 成功，无新增 error（warning 可忽略）

### 6.3 翻译质量

- [ ] 中文翻译自然、无机翻痕迹
- [ ] Provider/Model 专有名词保持英文
- [ ] 占位符 `{0}` `{1}` 在中英文中位置合理
- [ ] 无缺失翻译（运行时不会显示 key 字符串）

## 七、回滚方案

若上线后发现严重问题：

1. **快速回滚**：`git revert` 回退提交，重新 `node build.js` + copy + 重启
2. **降级方案**：删除 `LanguageSelector` 组件，恢复硬编码英文，保留 i18n 模块不删（不影响功能）
3. **最坏情况**：从 `dev` 分支 checkout 到上一个 commit
