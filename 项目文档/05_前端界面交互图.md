## 1. 整体 UI 架构总览

Void 编辑器在 VSCode 基础上叠加了一套 **React "岛屿" UI**，覆盖以下区域：

```
┌─────────────────────────────────────────────────────────┐
│  Onboarding Overlay（首次启动全屏覆盖层）               │
├──────┬──────────────────────────────────────────────────┤
│      │  编辑器主区域                                     │
│  侧  │  ┌──────────────────────────────────────────┐    │
│  边  │  │  Selection Helper (选区浮层)              │    │
│  栏  │  │  Quick Edit Zone (Ctrl+K 内联编辑框)      │    │
│  AI  │  │  Command Bar (代码变更导航栏)             │    │
│  聊  │  └──────────────────────────────────────────┘    │
│  天  │                                                   │
├──────┴──────────────────────────────────────────────────┤
│  Settings 面板（独立 Webview 页）                        │
└─────────────────────────────────────────────────────────┘
```

**React 组件入口文件映射：**

| UI 区域 | 入口组件 | 源码路径 |
|---------|---------|---------|
| Onboarding | `VoidOnboarding` | `void-onboarding/VoidOnboarding.tsx` |
| 侧边栏聊天 | `Sidebar` → `SidebarChat` | `sidebar-tsx/Sidebar.tsx` / `SidebarChat.tsx` |
| 快速编辑 | `QuickEdit` → `QuickEditChat` | `quick-edit-tsx/QuickEdit.tsx` / `QuickEditChat.tsx` |
| 选区辅助 | `VoidSelectionHelper` | `void-editor-widgets-tsx/VoidSelectionHelper.tsx` |
| 命令栏 | `VoidCommandBar` | `void-editor-widgets-tsx/VoidCommandBar.tsx` |
| 设置面板 | `Settings` | `void-settings-tsx/Settings.tsx` |

## 2. Onboarding 引导流程

### 2.1 触发条件

当 `globalSettings.isOnboardingComplete === false` 时，Void 启动后显示全屏覆盖的 Onboarding 流程。

### 2.2 页面流程

```
Page 0: 欢迎页
  ├── Void Logo + "Welcome to Void" 标题
  ├── 语言选择器（LanguageSelector：中文/English 切换按钮组）
  └── "Get Started →" 按钮 → 跳转 Page 1

Page 1: 添加 AI 服务提供商（AddProvidersPage）
  ├── 左侧面板
  │   ├── Tab 选项卡（3 个 Tab）
  │   │   ├── 默认（aiyiwei）
  │   │   ├── 本地（Ollama / vLLM / LM Studio）
  │   │   └── 兼容（OpenAI Compatible）
  │   └── 功能检查清单（Chat ✓, Quick Edit ✓, Autocomplete ✓, Apply ✓, SCM ✓）
  ├── 右侧面板
  │   ├── 服务商配置表单（API Key 输入框等）
  │   ├── 获取模型 / 测试连接按钮（aiyiwei 专用）
  │   ├── 模型列表（ModelDump：展示可用模型，可搜索/开关/添加）
  │   └── 上一步 / 下一步 按钮
  └── 验证逻辑：必须有可用 Chat 模型才能进入下一步

Page 2: 设置与主题迁移
  ├── "Settings & Themes" 标题
  ├── 一键迁移按钮
  │   ├── Transfer from VS Code
  │   ├── Transfer from Cursor
  │   └── Transfer from Windsurf
  └── "Enter the Void →" 完成按钮
      └── 触发：setGlobalSetting('isOnboardingComplete', true)
      └── 同步：将 React locale 写入 VSCode argv.json / localeService
```

### 2.3 关键交互说明

| 操作 | 行为 |
|------|------|
| 语言切换 | 即时切换 React UI 语言，完成 Onboarding 时同步到 VSCode 原生 locale |
| 获取模型按钮 | 调用 `refreshModelService.startRefreshingModels()`，成功后自动启用 provider |
| 测试连接按钮 | 调用 `llmMessageService.openAICompatibleList()` 验证 API 连通性 |
| 一键迁移 | 调用 `extensionTransferService.transferExtensions()` 导入扩展和设置 |
| 重做 Onboarding | 在 Settings 页点击 "Redo Onboarding" 按钮 |

## 3. 侧边栏 AI 聊天（Sidebar Chat）

### 3.1 整体布局

```
┌──────────────────────────────┐
│   落地页（Landing Page）       │  ← 无对话时显示
│   ┌────────────────────────┐ │
│   │  输入框（VoidChatArea） │ │
│   │  ├─ 文件选择标签        │ │
│   │  ├─ 文本输入区          │ │
│   │  ├─ ChatMode 下拉       │ │
│   │  ├─ Model 下拉          │ │
│   │  ├─ Reasoning 滑块      │ │
│   │  └─ 发送/停止 按钮      │ │
│   └────────────────────────┘ │
│                              │
│   建议提示 / 历史对话列表     │
└──────────────────────────────┘

┌──────────────────────────────┐
│   对话页（Thread Page）        │  ← 有对话时显示
│   ┌────────────────────────┐ │
│   │  CommandBar In Chat     │ │  ← 文件变更概览栏
│   │  (变更文件数 + Accept/  │ │
│   │   Reject All + 状态)    │ │
│   └────────────────────────┘ │
│   ┌────────────────────────┐ │
│   │  消息流                 │ │
│   │  ├─ User Bubble         │ │
│   │  ├─ Assistant Bubble    │ │
│   │  ├─ Tool Result         │ │
│   │  ├─ Checkpoint          │ │
│   │  └─ ... (可滚动)        │ │
│   └────────────────────────┘ │
│   ┌────────────────────────┐ │
│   │  输入框（同上）          │ │
│   └────────────────────────┘ │
└──────────────────────────────┘
```

### 3.2 输入区域（VoidChatArea）

**组成元素：**
- **文件选择标签（SelectedFiles）**：显示已添加的文件/代码选区/文件夹上下文
  - 标签类型：`File`（文件图标）、`CodeSelection`（文本图标，含行号范围）、`Folder`（文件夹图标）
  - 点击标签：打开对应文件 / 跳转到选区
  - 点击 X：移除上下文
  - 浅色标签：推荐文件（prospective），点击后变为正式选择
- **文本输入框（VoidInputBox2）**：支持 `@` 提及（文件/文件夹/代码选区）
- **ChatMode 下拉菜单**：选择对话模式（仅 Chat 功能显示）
- **Model 下拉菜单**：选择 AI 模型
- **Reasoning 选项滑块**：控制推理深度
- **发送按钮（↑ 箭头）**/ **停止按钮（■ 方块）**：根据流式状态切换

**快捷键：**
- `Enter`：发送消息
- `Shift+Enter`：换行
- `Escape`（流式中）：中止生成

### 3.3 消息气泡类型

#### 用户消息（UserMessageComponent）
```
┌─────────────────────────────┐
│  [附件文件标签]              │  ← SelectedFiles (past)
│  用户输入的文字内容           │
│                     [✏️][↩️] │  ← 悬停显示：编辑/回退按钮
└─────────────────────────────┘
```

- **编辑模式**：点击消息或铅笔图标进入编辑模式，出现可编辑输入框 + 重新提交按钮
- **回退按钮（Undo2 图标）**：当消息有 `turnId` 时显示，点击调用 `turnCheckpointService.revertTo()` 回退文件到该轮次之前的状态

#### 助手消息（AssistantMessageComponent）
```
┌─────────────────────────────┐
│  ▶ Reasoning（可折叠）       │  ← 推理过程，流式时自动展开
│    推理思考内容...            │
├─────────────────────────────┤
│  Markdown 渲染的回复内容      │  ← 支持代码块高亮、链接检测
│  ```代码块``` 含 Apply 按钮  │
└─────────────────────────────┘
```

#### 工具结果消息（ToolResult）

每个工具调用以可折叠卡片形式展示：

```
┌─────────────────────────────────────────────┐
│ ▶ [工具标题]  [文件名]     [状态/操作按钮]   │
│   ┌─────────────────────────────────────┐   │
│   │  展开内容（代码diff/搜索结果/终端）  │   │
│   └─────────────────────────────────────┘   │
│   ▶ Lint Errors（可折叠）                    │
└─────────────────────────────────────────────┘
```

**内置工具 UI 映射：**

| 工具名 | 卡片标题 | 展开内容 | 操作按钮 |
|--------|---------|---------|---------|
| `read_file` | Read File | 无（点击跳转文件） | — |
| `edit_file` | Edited File | Diff 对比视图 | Accept / Reject / Copy |
| `rewrite_file` | Rewrote File | 代码预览 | Accept / Reject / Copy |
| `run_command` | Ran Command | 终端输出（运行时附加真实终端） | — |
| `run_persistent_command` | Ran Persistent Command | Shell 输出 | — |
| `ls_dir` | Listed Directory | 子项列表（可点击） | — |
| `get_dir_tree` | Got Directory Tree | 树形结构代码块 | — |
| `search_pathnames_only` | Searched Filenames | 匹配文件列表 | — |
| `search_for_files` | Searched Files | 匹配文件列表 | — |
| `search_in_file` | Searched In File | 匹配行预览 | — |
| `create_file_or_folder` | Created File/Folder | — | 点击跳转 |
| `delete_file_or_folder` | Deleted File/Folder | — | 点击跳转 |
| `read_lint_errors` | Read Lint Errors | Lint 错误列表 | — |
| `open_persistent_terminal` | Opened Terminal | — | 点击聚焦终端 |
| `kill_persistent_terminal` | Killed Terminal | — | — |
| MCP 工具 | Called [ServerName] | JSON 结果（Markdown 渲染） | Copy 输入参数 |

#### 工具审批按钮（ToolRequestAcceptRejectButtons）

当工具需要用户批准时，在工具卡片下方显示：

```
[ Approve ] [ Cancel ] [ Trust This Session ] [ Trust Always ]
```

- **Approve**：批准执行当前工具调用
- **Cancel**：拒绝执行
- **Trust This Session**：本次会话自动批准该类工具（edits/terminal/MCP）
- **Trust Always**：永久自动批准该类工具（写入全局设置）

#### Checkpoint 标记

```
                    Checkpoint
```
- 显示在对话流中，表示一个可回退的时间点
- 点击 Checkpoint：跳转回该检查点，之后的消息变为半透明（ghost 状态）
- 运行中或其他线程运行时禁用点击

### 3.4 聊天内命令栏（CommandBarInChat）

位于输入框上方，在有文件变更时显示：

```
┌──────────────────────────────────────────────┐
│  [▼ 展开/折叠] 3 files with changes  [✕][✓]  │  ← Reject All / Accept All
│  ┌────────────────────────────────────────┐  │
│  │  main.ts    2 diffs     [✕][✓]  ● Done │  │  ← 逐文件操作
│  │  utils.ts   1 diff      [✕][✓]  ● Done │  │
│  │  app.tsx    3 diffs      ---    ◯ Run  │  │
│  └────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘
```

- 显示文件变更数量和线程状态指示灯（Running=橙 / Needs Approval=黄 / Done=灰）
- 每个文件可单独 Accept / Reject
- 自动展开/折叠逻辑：有变更时自动展开，用户手动关闭后不再自动展开

### 3.5 落地页

无对话时显示落地页：
- 输入框
- 建议提示（如有历史对话则显示 "Previous Threads" 列表，否则显示推荐提示）
- 推荐提示示例：代码总结、Rust 类型转换、voidrules 等

## 4. 快速编辑（Quick Edit / Ctrl+K）

### 4.1 触发方式

在编辑器中选择代码后按 `Ctrl+K`，在选区位置弹出内联编辑框。

### 4.2 界面结构

```
┌── 编辑器代码区 ──────────────────────┐
│  ...                                  │
│  ┌─── QuickEditChat ──────────────┐  │
│  │  输入提示文字框                  │  │
│  │  ├─ Model 下拉                  │  │
│  │  └─ 发送(↑) / 停止(■) / 关闭(×)│  │
│  └─────────────────────────────────┘  │
│  ...                                  │
└───────────────────────────────────────┘
```

### 4.3 交互说明

| 操作 | 行为 |
|------|------|
| 输入指令 + Enter | 发送编辑请求，AI 直接修改选区代码 |
| Escape | 关闭 Quick Edit 区域并取消流式 |
| 点击 × | 同 Escape |
| 流式中点击 ■ | 中止生成 |

- 最大宽度 450px
- 输入框高度自适应（ResizeObserver 监听）
- 模型使用 `Ctrl+K` feature 对应的模型配置

## 5. 代码选区辅助浮层（Selection Helper）

### 5.1 触发条件

在编辑器中选择一段代码后，自动在选区附近弹出浮层。

### 5.2 界面结构

```
┌──────────────────────────┐
│  [Ctrl+L]  |  [Ctrl+K]  │  ← 默认视图：两个快捷键按钮
└──────────────────────────┘

或展开更多：

┌──────────────────────────────┐
│  [Ctrl+L] | [Ctrl+K] | [⋮] │
│  ┌──────────────────────┐   │
│  │  更多操作...           │   │  ← 点击 ⋮ 展开
│  └──────────────────────┘   │
└──────────────────────────────┘
```

### 5.3 交互说明

- **Ctrl+L 按钮**：将选中代码添加到侧边栏 Chat 作为上下文
- **Ctrl+K 按钮**：在选区位置打开 Quick Edit
- 点击任一选项后浮层自动关闭
- 重新选择代码时浮层重新出现

## 6. 命令栏（Command Bar）

### 6.1 触发条件

当编辑器中有 AI 产生的代码变更（diff areas）时，在编辑器顶部显示浮动命令栏。

### 6.2 界面结构

```
完整视图（当前文件有变更时）：
┌──────────────────────────────────────────────────────────────┐
│ [↑][Diff 2 of 5][↓] | [←][File 1 of 3][→] | [Accept][Reject] | [⋮] │
└──────────────────────────────────────────────────────────────┘

展开 Accept All / Reject All：
                                    ┌──────────────────────┐
                                    │ [Accept All][Reject All] │
                                    └──────────────────────┘
┌──────────────────────────────────────────────────────────────┐
│ [↑][Diff 2 of 5][↓] | [←][File 1 of 3][→] | [Accept][Reject] | [⋮] │
└──────────────────────────────────────────────────────────────┘

简化视图（当前文件无变更，但其他文件有）：
┌──────────────────────────────────┐
│  3 files changed  [Next →]       │
└──────────────────────────────────┘
```

### 6.3 交互说明

| 按钮 | 功能 | 快捷键 |
|------|------|--------|
| ↑ / ↓ | 在当前文件内的 diff 间导航 | 对应 keybinding |
| ← / → | 在有变更的文件间导航 | 对应 keybinding |
| Accept File | 接受当前文件所有变更 | 对应 keybinding |
| Reject File | 拒绝当前文件所有变更 | 对应 keybinding |
| ⋮ (菜单) | 展开 Accept All / Reject All（全部文件） | — |
| Accept All | 接受所有文件的所有变更 | 对应 keybinding |
| Reject All | 拒绝所有文件的所有变更 | 对应 keybinding |

### 7.3 各 Tab 功能说明

#### Models（模型管理）
- **模型列表（ModelDump）**：
  - 搜索框（超过 5 个模型时显示）
  - 每个模型显示：提供商名 | 模型名 | 高级设置(+) | 状态标记(★) | 开关 | 删除(×)
  - 高级设置对话框（SimpleModelSettingsDialog）：JSON 编辑器覆盖模型参数（contextLength、maxTokens 等）
- **添加自定义模型**：选择提供商 → 输入模型名 → Add
- **自动检测本地模型**：开关控制是否自动刷新 Ollama/vLLM 等本地模型
- **可刷新模型源**：手动刷新按钮

#### Local Providers（本地提供商）
- Ollama 安装说明（步骤 1-3）
- vLLM / LM Studio 配置表单
- 每个提供商的 API 设置输入框

#### Providers（远程提供商）
- 非本地提供商列表（Anthropic、OpenAI、Gemini、DeepSeek、OpenRouter 等）
- 每个提供商：API Key 输入框 + 可选的 Base URL

#### Feature Options（功能选项）

| 子区 | 设置项 |
|------|--------|
| **Autocomplete** | 启用开关 + 模型选择（仅 FIM 模型） |
| **Apply** | 同步 Chat 模型开关 + 独立模型选择 + Fast/Slow Apply 切换 |
| **Tools** | 信任级别选择器（Conservative / Standard / Seamless） |
|  | 高级审批面板（可展开：逐项 edits/terminal/MCP 开关 + 终端命令白名单） |
|  | 推理策略（自适应推理预算：启用开关、默认级别、关键词触发、启发式、线程继承） |
|  | 自动修复 Lint 错误开关 |
|  | 自动接受 LLM 变更开关 |
| **Editor** | 内联建议显示开关 |
| **SCM** | 同步 Chat 模型开关 + 独立模型选择 |

#### General（通用设置）

| 子区 | 功能 |
|------|------|
| **One-Click Switch** | 从 VS Code / Cursor / Windsurf 一键迁移设置和扩展 |
| **Import/Export** | 导入/导出设置 JSON + 导入/导出聊天记录 JSON + 重置按钮（需二次确认） |
| **Built-in Settings** | 打开通用设置 / 键盘快捷键 / 主题选择 / 日志目录 |
| **Metrics** | 数据收集 Opt-Out 开关 |
| **AI Instructions** | 自定义 AI 系统指令文本框 + 禁用系统消息开关 |

#### MCP（Model Context Protocol）
- **添加 MCP 服务器**：打开 MCP 配置文件按钮
- **服务器列表（MCPServersList）**：
  - 每个服务器卡片：状态指示灯（绿=成功/红=错误/黄=加载中/灰=离线）+ 名称 + 开关
  - 展开显示：工具标签列表 + 启动命令 + 错误信息

## 8. 通用 UI 元素与交互模式

### 8.1 VoidChatArea（通用输入区容器）

所有 AI 交互入口（Chat、QuickEdit、消息编辑）共享此组件：

```
┌─────────────────────────────────┐
│  [文件标签] [文件标签] ...       │  ← SelectedFiles
│  ┌────────────────────────┐ [×] │  ← 输入框 + 可选关闭按钮
│  │  文字输入区（支持 @提及）│     │
│  └────────────────────────┘     │
│  [Reasoning▼] [Mode▼] [Model▼]  │  ← 底部行左
│                        [↑/■]    │  ← 底部行右：发送或停止
└─────────────────────────────────┘
```

### 8.2 模型下拉菜单（ModelDropdown）

- 按 feature（Chat / Ctrl+K / Autocomplete / Apply / SCM）独立选择模型
- 显示当前选中模型名称
- 下拉列表只显示未隐藏的模型

### 8.3 ChatMode 下拉菜单

- 仅在 Chat 功能的输入区显示
- 控制 AI 的对话模式（如 Agent 模式等）

### 8.4 Reasoning 选项滑块（ReasoningOptionSlider）

- 控制 AI 推理深度
- 按 feature 独立配置

### 8.5 Markdown 渲染（ChatMarkdownRender）

- 渲染助手回复中的 Markdown 内容
- 代码块支持语法高亮
- 代码块含 Apply 按钮（可将代码应用到编辑器）
- 链接检测和可点击

### 8.6 Diff 编辑器（VoidDiffEditor）

- 在 `edit_file` 工具结果中展示搜索/替换块的对比视图
- 可视化显示将要进行的代码变更

### 8.7 滚动行为

- 消息列表自动滚动到底部（ScrollToBottomContainer）
- 用户手动向上滚动时暂停自动滚动
- 新消息到达且已在底部时恢复自动滚动

### 8.8 错误处理

- 所有主要 UI 区域包裹在 `ErrorBoundary` 中
- 流式错误在消息列表底部显示（ErrorDisplay 组件）
- 可点击 "Open Settings" 快速排查配置问题
- 错误可手动 Dismiss

### 8.9 深色/浅色主题

- 所有 React 岛屿通过 `useIsDark()` 检测当前主题
- 外层容器添加 `dark` class 切换 Tailwind 暗色模式
- 颜色系统使用 `void-bg-*`、`void-fg-*`、`void-border-*` CSS 变量

## 9. 快捷键速查表

| 快捷键 | 功能 | 上下文 |
|--------|------|--------|
| `Ctrl+L` | 将选中代码/当前文件添加到 Chat 上下文 | 编辑器 |
| `Ctrl+K` | 在选区位置打开 Quick Edit | 编辑器 |
| `Enter` | 发送消息 | Chat / QuickEdit 输入框 |
| `Shift+Enter` | 换行 | Chat / QuickEdit 输入框 |
| `Escape` | 中止生成 / 关闭 QuickEdit / 取消编辑 | Chat / QuickEdit |
| Diff ↑ / ↓ | 上/下一个 diff | Command Bar |
| File ← / → | 上/下一个变更文件 | Command Bar |
| Accept File | 接受当前文件变更 | Command Bar |
| Reject File | 拒绝当前文件变更 | Command Bar |
| Accept All | 接受所有变更 | Command Bar |
| Reject All | 拒绝所有变更 | Command Bar |

> **注**：Diff 导航和 Accept/Reject 的具体快捷键由 keybinding 配置决定，可在 Settings → Built-in Settings → Keyboard Shortcuts 中查看和自定义。

## 附录：UI 交互流程图

### A. 典型 Chat 对话流程

```
用户打开侧边栏 Chat
    │
    ├─ 无历史对话 → 显示落地页（输入框 + 推荐提示）
    │                   │
    │                   ├─ 点击推荐提示 → 自动发送
    │                   └─ 手动输入 + Enter → 发送消息
    │
    └─ 有历史对话 → 显示落地页（输入框 + 历史对话列表）
                        │
                        └─ 选择历史对话 / 新建对话
                            │
                            ▼
                   显示对话页（消息流 + 输入框）
                            │
    ┌───────────────────────┤
    │                       ▼
    │              AI 开始流式回复
    │              ├─ 显示 Reasoning（可折叠）
    │              ├─ 显示 Markdown 回复
    │              ├─ 工具调用 → 显示工具卡片
    │              │   ├─ 需要审批 → [Approve] [Cancel] [Trust]
    │              │   │   ├─ Approve → 执行工具 → 显示结果
    │              │   │   └─ Cancel → 标记为 rejected
    │              │   └─ 自动批准 → 直接执行
    │              └─ 生成完成 → 更新 CommandBarInChat
    │                              │
    │                   ├─ Accept All → 接受所有变更
    │                   ├─ Reject All → 拒绝所有变更
    │                   └─ 逐文件 Accept / Reject
    │
    ├─ 点击用户消息 → 进入编辑模式 → 重新提交
    ├─ 点击 Undo 图标 → 回退到该轮次之前的文件状态
    ├─ 点击 Checkpoint → 跳转检查点（后续消息变灰）
    └─ Escape / 点击 ■ → 中止当前生成
```

### B. Quick Edit 流程

```
编辑器中选择代码
    │
    ├─ 显示 Selection Helper 浮层
    │   ├─ 点击 Ctrl+K → 打开 Quick Edit
    │   └─ 点击 Ctrl+L → 添加到 Chat 上下文
    │
    └─ 按 Ctrl+K → 直接打开 Quick Edit
        │
        ▼
    显示内联编辑框
        │
        ├─ 输入指令 + Enter → AI 修改代码
        │   └─ 变更显示为 inline diff → Command Bar 出现
        │       ├─ Accept → 接受变更
        │       └─ Reject → 拒绝变更
        │
        └─ Escape → 关闭 Quick Edit
```
