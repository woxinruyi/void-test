## 4. Void AI Agent 循环流程（最新）

```
┌─────────────────────────────────────────────────────────────────┐
│                  Void AI Agent 循环业务流程                       │
│           (chatThreadService.ts — 完整 Agent Loop)               │
└─────────────────────────────────────────────────────────────────┘

[1] 用户发送消息
    - 在侧边栏输入消息（支持 @-mention 文件/URL）
    - 选择模式：Agent / Gather / Normal
    ↓
[2] 创建 Turn 检查点 【Phase 2】
    turnCheckpointService.startTurn(threadId)
    - 记录本轮起始状态
    ↓
[3] 上下文压缩检查 【Phase 3】
    contextCompactionService.shouldCompact(messages, modelSelection)
    ├─ 若 token 占比 > 60% → 触发 LLM 摘要
    │   - 保留最近 10 条消息完整
    │   - 用 LLM 摘要替换旧消息
    └─ 否则 → 跳过
    ↓
[4] 构建系统提示 + 消息
    convertToLLMMessageService._generateChatMessagesSystemMessage()
    ├─ 工作区路径 + 目录结构
    ├─ 打开文件 + 活跃编辑器
    ├─ 最近修改文件列表 <recently_modified> 【Phase 3】
    ├─ 持久终端 ID
    ├─ .voidrules + AI 指令
    ├─ 内置工具定义（含 batch_edit）【Phase 3】
    └─ MCP 工具列表
    ↓
[5] 发送 LLM 请求
    LLMMessageService.sendLLMMessage() → IPC → 主进程
    ├─ 流式接收文本 + 推理 + 工具调用
    └─ 更新 streamState
    ↓
[6] 解析 LLM 响应
    ├─ 有工具调用 → 进入工具执行 [7]
    └─ 无工具调用 → 循环结束 [11]
    ↓
[7] PreToolUse Hook 检查 【Phase 2】
    hookService.runHooks('PreToolUse', ...)
    ├─ deny → 拒绝工具调用
    ├─ modify → 修改工具参数
    └─ allow → 继续
    ↓
[8] 工具执行
    ToolsService.callTool()
    ├─ 参数验证 (validateParams)
    ├─ 审批检查 (autoApprove / 用户审批)
    ├─ edit/rewrite/batch_edit → 添加编辑检查点 【Phase 2】
    ├─ 模糊匹配回退（exact → stripped → fuzzy LCS）【Phase 3】
    └─ 执行工具 + 格式化结果
    ↓
[9] PostToolUse Hook 【Phase 2】
    hookService.runHooks('PostToolUse', ...)
    ↓
[10] 工具结果加入消息历史
     └─ 回到步骤 [4]
    ↓
[11] Agent 循环结束
     ├─ LLM 无工具调用
     ├─ 达到最大重试次数
     ├─ 用户中断
     └─ Turn 检查点结束
```

## 5. 代码应用流程（最新）

```
┌─────────────────────────────────────────────────────────────────┐
│                   代码应用业务流程（含增强特性）                   │
└─────────────────────────────────────────────────────────────────┘

[1] 触发应用
    ├─ LLM 调用 edit_file → 单文件搜索替换
    ├─ LLM 调用 batch_edit → 多文件批量编辑 【Phase 3】
    ├─ LLM 调用 rewrite_file → 全文重写
    └─ 用户 Ctrl+K → 内联编辑
    ↓
[2] 编辑检查点记录 【Phase 2】
    turnCheckpointService.recordEdit(turnId, uri, content)
    - 保存编辑前文件快照
    - batch_edit 为每个文件分别记录
    ↓
[3] 文本定位（edit_file / batch_edit）
    editCodeService.findTextInCode()
    ├─ 第1层：精确匹配（exact string match）
    ├─ 第2层：空白规范化匹配（whitespace-stripped）
    └─ 第3层：行级模糊匹配 【Phase 3】
        ├─ normalizeLine() → 去空白/标点规范化
        ├─ lineSimilarity() → LCS 相似度计算 (0~1)
        └─ fuzzyFindLines() → 滑动窗口匹配 (threshold 0.7)
    ↓
[4] 创建 DiffZone
    editCodeService.ts
    - 标记需要修改的行范围
    - 计算原始/修改对比
    ↓
[5] 显示差异
    - 红色: 删除的行
    - 绿色: 新增的行
    - 用户可查看对比
    ↓
[6] 用户操作
    ├─ 接受 → 应用更改到文件
    ├─ 拒绝 → 取消更改（可回滚到 Turn 检查点）
    └─ 编辑 → 手动修改建议
    ↓
[7] Lint 错误收集
    - 等待 2s 后收集编辑后的 lint errors
    - batch_edit 为每个文件分别报告
    ↓
[8] 完成
```

## 9. 上下文压缩流程 【Phase 3 新增】

```
┌─────────────────────────────────────────────────────────────────┐
│                   上下文压缩（Context Compaction）                │
│                contextCompactionService.ts                       │
└─────────────────────────────────────────────────────────────────┘

[1] 触发检查
    Agent 循环每轮 LLM 调用前
    ↓
[2] 估算 token 占比
    shouldCompact(messages, modelSelection)
    ├─ 获取模型 contextWindow 大小
    ├─ 估算当前消息 token 总量（字符数 / CHARS_PER_TOKEN）
    └─ 若占比 > COMPACTION_THRESHOLD (60%) → 触发压缩
    ↓
[3] 分割消息
    compactMessages(messages, modelSelection)
    ├─ 保留最近 KEEP_RECENT_COUNT (10) 条消息完整
    └─ 将旧消息提取为对话文本
    ↓
[4] LLM 摘要生成
    _generateSummary(conversationText)
    ├─ 构造摘要请求（system + user prompt）
    ├─ 调用 LLMMessageService.sendLLMMessage()
    └─ 截断过长的输入（不超过 contextWindow 50%）
    ↓
[5] 替换旧消息
    ├─ 用摘要消息替代旧消息
    └─ 保留最近消息 + 摘要 = 新消息列表
    ↓
[6] 返回压缩后消息继续 Agent 循环
```

## 10. 内置工具体系总览 【最新】

```
┌─────────────────────────────────────────────────────────────────┐
│                      内置工具完整列表                             │
│              toolsServiceTypes.ts + prompts.ts                   │
└─────────────────────────────────────────────────────────────────┘

上下文获取工具（7 个）：
  ├─ read_file          读取文件内容（支持分页）
  ├─ ls_dir             列出目录内容
  ├─ get_dir_tree       获取目录树
  ├─ search_pathnames_only  搜索文件名
  ├─ search_for_files   搜索文件内容
  ├─ search_in_file     文件内搜索
  └─ read_lint_errors   读取 Lint 错误

编辑工具（5 个）：
  ├─ edit_file           搜索/替换块编辑（含模糊匹配）
  ├─ batch_edit          多文件批量编辑 【Phase 3 新增】
  ├─ rewrite_file        全文重写
  ├─ create_file_or_folder  创建文件/文件夹
  └─ delete_file_or_folder  删除文件/文件夹

终端工具（4 个）：
  ├─ run_command          运行命令并等待
  ├─ open_persistent_terminal  打开持久终端
  ├─ run_persistent_command    持久终端运行命令
  └─ kill_persistent_terminal  关闭持久终端

审批分类 (approvalType)：
  ├─ edits    → edit_file, batch_edit, rewrite_file, create/delete
  ├─ terminal → run_command, run_persistent_command, open/kill terminal
  └─ none     → 所有上下文获取工具（自动通过）
```

## 12. Turn 检查点与回滚流程 【Phase 2 新增】

```
┌─────────────────────────────────────────────────────────────────┐
│              Turn 检查点 / 回滚机制                               │
│             turnCheckpointService.ts                             │
└─────────────────────────────────────────────────────────────────┘

[1] 用户发送消息 → 创建 Turn
    turnCheckpointService.startTurn(threadId)
    ↓
[2] 工具执行时记录操作
    ├─ edit_file / rewrite_file → recordEdit(turnId, uri, oldContent)
    ├─ batch_edit → 为每个文件分别 recordEdit 【Phase 3】
    ├─ create_file_or_folder → recordCreate(turnId, uri)
    ├─ delete_file_or_folder → recordDelete(turnId, uri, oldContent)
    └─ run_command → recordCommand(turnId, cmd, cwd)
    ↓
[3] Turn 结束
    - Agent 循环完成时自动结束
    - 所有操作快照已持久化
    ↓
[4] 用户触发回滚（可选）
    ├─ UI 显示"↶ 回滚到此处"按钮
    ├─ 恢复编辑前文件快照
    ├─ 撤销创建的文件
    └─ 外部修改冲突检测
```
